[[create]]
== Create an Alert

Configure an alert, the condition for triggering the alert, and the alert notification.

. From *Alerts* in Anypoint Monitoring, click *Create Alert*. 
. Configure alert properties:
.. Provide a name for the alert.
.. Select the <<environment, environment>> in your organization for this alert. 
//TODO: IS "resource" the term we'll use; check on final name in UI. Was "entity" and "entity type"
.. Select the resource type and resource that the alert is for. Only active resources that can receive traffic are available.

* *Resource Type*: *API* or *Mule Application*
* *Resource:* Name of the API or Mule application 
.. For an API alert, select an API version and up to ten response codes. 
.. Click *Next* to open *Set Alert Condition*. 
. In *Set Alert Condition*, configure the criteria for triggering the alert:
.. Select the <<metrics, metric>> that the alert uses.
.. Select the <<severity, severity>> of the alert.
.. Provide a <<threshold, threshold>> for triggering the alert.
.. Click *Next* to open *Configure Email Notification*. 
. In *Configure Email Notification*, configure the email to send when the alert triggers.
+
To use variables in the email, see <<variables>>.

.. Provide a subject.
.. Provide the message.
.. Identify recipients.

[[threshold]]
== Alert Conditions

Alert condition configurations indicate when the data collected on a <<alert-metrics, metric>> triggers the alert. Configurations for alert thresholds follow this form:

//TODO: VERIFY THE Above/Below; verify variable replacement of "selected metric" with name of metric

[%header,cols="1a,1a"]
|===
| Configuration Pattern | Example 
| *Trigger alert when selected metric is _Above\|Below_ _Number_ for each of the last _Number_ consecutive minutes.*
| *Trigger alert when selected metric is _Above_ _4_ for each of the last _10_ consecutive minutes.*
|===

The example configures an alert to trigger when the selected metric (such as *Message Count*) is *Greater than or equal to* (`>=`) 4 for 10 consecutive minutes. In other words, the count must meet the criteria for each minute of minutes 1-10. For example, if the count is `>=` 4 for 9 of 10 minutes, but not for the tenth minute, the alert doesn't trigger, even if the count reaches 4 at minute 11. Following the same criteria, if the count is `>=` 4 for minutes 11-20, the alert triggers.

[[metrics]]
== Alert Metrics

A Mule application or API metric is part of the <<threshold, configuration for triggering the alert>>. 

Mule app metrics:

* *Message Count*: Total number of Mule messages that processed successfully
* *Message Error Count*: Number of Mule messages that return an exception in a flow
* *Average Response Time*: Response time (in milliseconds) of a message
* *CPU Utilization*: Percent of CPU used on the virtual machine 
+
This metric includes all processes and is available only for apps deployed to CloudHub or Anypoint Runtime Fabric.
* *Memory Utilization*:
Percent of heap used
+
This metric is available only for apps deployed to CloudHub or Anypoint Runtime Fabric.
+
Anypoint Monitoring tracks heap usage and triggers memory alerts based on the value of `heap_used`/`heap_total`. Note that `heap_total` isn't identical to the maximum heap memory allocated to the Mule app on CloudHub. For example, 0.2 vCores indicates that the maximum heap memory is 1 GB (see the table in xref:cloudhub::cloudhub-architecture.adoc#cloudhub-workers[CloudHub Workers]), but the value of `heap_total` isn't 1GB. Instead, `heap_total` is the maximum amount of memory that the JVM can use for heap memory, where objects are created and stored. In Java, this value changes dynamically depending on memory fragmentation, garbage collection, and other memory management features. For more information about the JVM Heap Total Memory values, see xref:dashboard-config-ref.adoc#metrics_advanced[].
* *Thread Count*:
Total number of threads used
+
This metric is available only for apps deployed to CloudHub or Anypoint Runtime Fabric.


API metrics:

* *Total Request Count*: ::
Sum of requests in the selected time period for the given API
+
Data is aggregated in one minute increments.
* *Average Response Time*: Average response time of requests in the selected time period for the given API
+
Data is aggregated in one minute increments.
* *Response Codes*: Sum of HTTP response codes that occur in the selected time period
