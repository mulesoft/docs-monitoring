[[find]]
== Find Alerts

To find the list of alerts:

. In Anypoint Monitoring, navigate to *Alerts*.
//. To narrow the list of alerts, use any of these filtering options:
//
//* <<status, Status>> 
//* <<severity, Severity>>
//* <<search, Search>> 
. To narrow the list of alerts, <<search, search>> for an alert name. 
+
The search field accepts partial word searches.
. Review the alert list that returns. 
+
Each alert provides:

* *Alert Name*: Name of the alert
* *Severity*: Configured <<severity, severity>> of the alert
* *Status*: Current <<status, Status>> of the alert
* *Metric*: Name of the <<metrics, metric>> that the alert reports
//NOT SUPPORTED YET:
//* *Entity*: Name of the Mule app or API that the alert is for
* *Last Alerted*: Most recent date and time the alert triggered or *-* for an alert that has never triggered
* *Creation Date*: Alert creation date and time
* *Availability*: *Enabled* or *Disabled* alert setting

[[create]]
== Create an Alert

Configure an alert, the condition for triggering the alert, and the alert notification.

. From *Alerts* in Anypoint Monitoring, click *Create Alert*. 
. Configure alert properties:
.. Provide a name for the alert.
.. Select the <<environment, environment>> in your organization for this alert. 
//TODO: IS "resource" the term we'll use 
.. Select the <<entities, resource type and resource>> that the alert is for. 
.. Click *Next* to open *Set Alert Condition*. 
. In *Set Alert Condition*, configure the criteria for triggering the alert:
.. Select the <<metrics, metric>> that the alert uses.
.. Select the <<severity, severity>> of the alert.
.. Provide a <<threshold, threshold>> for triggering the alert.
.. Click *Next* to open *Configure Email Notification*. 
. In *Configure Email Notification*, configure the email to send when the alert triggers.
+
To use variables in the email, see <<variables>>.
.. Provide a subject.
.. Provide the message.
.. Identify recipients.

[[threshold]]
== Alert Thresholds

Alert thresholds indicate when the value of a metric triggers the alert. Threshold configurations follow this form:

//TODO: VERIFY THE Above/Below
*Trigger alert when selected metric is [Above|Below] [Number] for each of the last [Number] consecutive minutes.*

Example:

*Trigger alert when Message Count is Above 4 for each of the last 10 consecutive minutes.*

The example configures an alert to trigger when the selected metric (*Message Count*) is greater than (*Above*) 4 for 10 consecutive minutes. In other words, the count must exceed 4 for each minute of minutes 1-10.  For example, if the count is greater than 4 for 9 of 10 minutes, but not for the tenth minute, the alert does not trigger, even if the count reaches 4 at minute 11. Following the same rule, if the count is greater than 4 for minutes 11-20, the alert triggers.

== Metrics

A Mule application or API metric is part of the <<threshold, configuration for triggering the alert>>. 

Mule app metrics:

* *Message Count*: Total number of Mule messages that are processed successfully
* *Message Error Count*: Number of Mule messages that return an exception in a flow
* *Average Response Time*: Response time (in milliseconds) of a message
* *CPU Utilization*: Percent of CPU used on the virtual machine 
+
This metric includes all processes and is available only for apps deployed to CloudHub or Anypoint Runtime Fabric.
* *Memory Utilization*:
Percent of heap used
+
This metric is available only for apps deployed to CloudHub or Anypoint Runtime Fabric.
+
Anypoint Monitoring tracks heap usage and triggers memory alerts based on the value of `heap_used`/`heap_total`. Note that `heap_total` isn't the identical to the maximum heap memory allocated to the Mule app on CloudHub. For example, 0.2 vCores indicates that the maximum heap memory is 1 GB (see the table in xref:cloudhub::cloudhub-architecture.adoc#cloudhub-workers[CloudHub Workers]), but the value of `heap_total` isn't 1GB. Instead, `heap_total` is the maximum amount of memory that the JVM can use for heap memory, where objects are created and stored. In Java, this value changes dynamically depending on memory fragmentation, garbage collection, and other memory management features. For more information about the JVM Heap Total Memory values, see xref:dashboard-config-ref.adoc#metrics_advanced[].
* *Thread Count*:
Total number of threads used
+
This metric is available only for apps deployed to CloudHub or Anypoint Runtime Fabric.


API metrics:

* *Total Request Count*: ::
Sum of requests in the selected time period for the given API
+
Data is aggregated in one minute increments.
* *Average Response Time*: Average response time of requests in the selected time period for the given API
+
Data is aggregated in one minute increments.
* *Response Codes*: Sum of HTTP response codes that occur in the selected time period
